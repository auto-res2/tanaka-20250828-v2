\title{RASST: Unifying Parameter- and Activation-Efficient Training on Commodity GPUs}

\author{AIRAS}

\begin{document}

\maketitle

\begin{abstract}
Training 50-300M parameter transformers on 8-16 GB GPUs remains difficult because memory scales along two axes: (1) parameters plus optimizer states, which commonly require multiple copies of the weights, and (2) the full activation stack needed for backpropagation. Prior approaches typically alleviate only one axis-reversible layers reduce activation memory, PEFT/LoRA reduces trainable parameters, and in-place operators trim specific buffers-leaving end-to-end pretraining or substantial fine-tuning out of reach on a single consumer GPU. We propose RASST, a Reversible Adapter-Shared Structured Transformer that jointly collapses both memory axes. RASST integrates: a reversible residual backbone to recompute activations; a frozen int8, per-channel-scaled, structured unrestricted-rank base shared across layers; low-rank adapters with ReLoRA-style periodic merges to accumulate high rank while bounding optimizer state; in-place normalization and activation layers; and blockwise attention and chunked FFN for near-linear memory growth with sequence length. We detail a reproducible evaluation plan with token-budget matching, strong baselines (vanilla with checkpointing, Reformer-like reversible, MEFT, LoRA-style, Tempo), WikiText-103 pretraining, and GLUE fine-tuning. A sanity run on a tiny synthetic model already shows a 19\% reduction in peak allocated memory versus vanilla, validating the code path; we analyze the micro-scale throughput overhead and lay out ablations, long-context scaling, and low-precision robustness to complete validation.
\end{abstract}

\section{Introduction}
\subsection{Motivation and Challenges}
Transformer pretraining and adaptation have advanced language modeling but are often inaccessible to low-resource labs and on-device learners due to GPU memory limits. Even models with 50-300M parameters routinely exceed 20 GB during training once we account for multiple optimizer copies of parameters and the full stack of saved activations for backpropagation. Existing techniques usually address only one dimension. Reversible residual layers reconstruct activations during the backward pass to reduce activation memory \cite{kitaev-2020-reformer}. Parameter-efficient transfer learning (PEFT) tunes a small fraction of parameters to reduce optimizer state. Systems work has introduced in-place operator variants that lower specific buffer footprints \cite{andoorveedu-2022-tempo}. Yet, to our knowledge, no single architecture has simultaneously maintained both parameter-state and activation memory below an 8-16 GB envelope for end-to-end pretraining and substantial fine-tuning while safeguarding accuracy and speed.

\subsection{RASST Overview}
We introduce RASST, a Reversible Adapter-Shared Structured Transformer, designed to jointly collapse both memory axes. RASST composes five orthogonal ideas. First, a reversible residual skeleton reconstructs per-layer activations instead of storing them, making activation memory largely independent of depth \cite{kitaev-2020-reformer}. Second, for every projection in attention and feedforward, the weight matrix \(W\) is expressed as \(W = U_s + \Delta\), where \(U_s\) is a frozen, 8-bit, per-channel-scaled shared base reused across layers and \(\Delta\) is a trainable low-rank update; mild structure in \(U_s\) follows the spirit of structured unrestricted-rank matrices (SURM) to preserve expressiveness at low memory \cite{sehanobish-2024-structured}. Third, we periodically merge \(\Delta\) into \(U_s\) following ReLoRA, accumulating high-rank training signal while bounding the number of active trainable parameters and thus the optimizer state \cite{lialin-2023-relora}. Fourth, in-place-friendly normalization and activation layers further reduce transient buffers without destabilizing training. Fifth, blockwise attention and chunked FFN bound workspace memory and promote near-linear growth with sequence length on a single device \cite{liu-2023-blockwise}. Optionally, we apply K-FAC-reduce to adapters only and store curvature factors on CPU to limit GPU memory \cite{eschenhagen-2023-kronecker}.

\subsection{Practical Scenarios}
RASST targets two practical scenarios. First, democratized research: enabling pretraining and rigorous fine-tuning of 100-300M parameter language models on commodity 8-16 GB GPUs. Second, resource-constrained personalization and edge learning: weight-only quantization and bounded memory motivate architectures that remain efficient during both training and inference. RASST complements long-context techniques such as RingAttention and attention approximations and reversible PEFT \cite{liao-2023-make} by providing an integrated single-device design focused on both parameter and activation footprints.

\subsection{System Interactions and Risks}
The central challenge is making these ideas cohere without degrading accuracy or throughput. Reversibility introduces recomputation overhead \cite{kitaev-2020-reformer}; quantized shared bases require careful scaling and structure to avoid underfitting \cite{sehanobish-2024-structured}; low-rank adapters may saturate unless periodically merged \cite{lialin-2023-relora}; in-place approximations must be numerically stable; and blockwise kernels should avoid performance regressions \cite{liu-2023-blockwise}. We address these interactions through a unified architecture and evaluation procedure with matched token budgets, strong baselines, and extensive instrumentation.

\subsection{Contributions}
\begin{itemize}
  \item \textbf{Unified architecture}: reduces both activation and parameter-state memory by combining reversible blocks, shared int8 structured bases across layers, and low-rank adapters with periodic ReLoRA merges.
  \item \textbf{In-place and blockwise operators}: integrates in-place-friendly normalization and activation plus blockwise attention and chunked FFN to further reduce buffers while preserving throughput.
  \item \textbf{Reproducible evaluation}: provides a token-budget-matched protocol with multiple seeds and strong baselines (vanilla with checkpointing, Reformer-like reversible, MEFT, LoRA-style, Tempo) for WikiText-103 pretraining and GLUE fine-tuning.
  \item \textbf{Sanity run and tooling}: demonstrates a measurable peak-memory reduction versus vanilla in a tiny synthetic setting, validating the code path and instrumentation.
\end{itemize}

\subsection{Validation Plan}
We verify feasibility in stages. A tiny synthetic run validates the code path and measurement tooling and shows a clear memory reduction. The main study will compare RASST against baselines on peak memory, throughput, validation perplexity, and robustness under matched token budgets, and it will include ablations that isolate the impact of reversibility, in-place operations, shared structured bases, and adapter rank. We also plan long-context scaling measurements and weight-only int8 robustness experiments. Finally, we outline future directions including learned SURM structures, FFT-friendly multiplies for inference, reinforcement-guided dynamic layer tying, and KV-cache compression for long-context inference.

\section{Related Work}
\subsection{Activation-Efficient Training}
Reversible residual networks reconstruct intermediate activations during backpropagation, eliminating the need to cache per-layer activations. Reformer popularized reversible residuals in Transformers and demonstrated large memory savings, especially for long sequences \cite{kitaev-2020-reformer}. MEFT introduces adapters to preserve the pretrained model's starting point while enabling a reversible formulation, substantially reducing activation memory during fine-tuning \cite{liao-2023-make}. Tempo presents in-place-friendly variants of GELU, LayerNorm, and attention that reduce training memory and enable larger batch sizes and higher throughput \cite{andoorveedu-2022-tempo}. RASST adopts a reversible backbone for activation savings, augments it with in-place operators for further buffer reductions, and crucially targets parameter-state memory at the same time.

\subsection{Parameter-Efficient Adaptation}
PEFT methods such as adapters, prefix/prompt tuning, and low-rank updates tune a small number of parameters while keeping the backbone frozen. SURM introduces structured unrestricted-rank matrices that can match or exceed the expressiveness of low-rank approaches for a similar parameter budget \cite{sehanobish-2024-structured}. ReLoRA shows that periodic merging of low-rank updates into the base approximates high-rank training while maintaining a small active optimizer state \cite{lialin-2023-relora}. RASST leverages a single shared int8 structured base across layers and combines it with low-rank adapters plus ReLoRA-style merges to bound optimizer state while preserving expressive capacity.

\subsection{Long-Context and Memory-Friendly Attention}
Blockwise Parallel Transformers process attention and feedforward in blocks to reduce workspace memory and enable training with much longer sequences \cite{liu-2023-blockwise}. RingAttention distributes context across devices and overlaps communication with computation \cite{liu-2023-ringattention}. Approximate attention methods reduce complexity using random features, KDE-based acceleration, or kernel re-interpretations. RASST focuses on single-device constraints and uses blockwise kernels to bound per-layer workspaces; multi-device methods remain complementary.

\subsection{Second-Order Optimization under Weight Sharing}
K-FAC has been extended to architectures with weight sharing and can reduce the number of steps to target performance. The K-FAC-reduce variant is efficient and amenable to CPU storage of curvature factors \cite{eschenhagen-2023-kronecker}. RASST confines K-FAC to the small adapter parameters to further limit GPU memory.

\subsection{Compare and Contrast}
Reformer and MEFT primarily target activation memory and leave parameter-state growth largely intact. LoRA-style PEFT reduces trainable parameters but keeps the activation stack \cite{he-2021-towards}. Tempo lowers forward and backward buffer footprints but does not obviate activation storage in non-reversible stacks \cite{andoorveedu-2022-tempo}. SURM emphasizes expressive parameter efficiency but does not directly address activation memory \cite{sehanobish-2024-structured}. BPT and RingAttention prioritize long-context scaling. In contrast, RASST is an integrated single-device design that simultaneously collapses activation and parameter-state memory within a standard Transformer.

\subsection{Applicability and Evaluation}
All compared methods apply to transformer language models. Our evaluation plan includes Reformer-like (reversible only), MEFT, LoRA-style, Tempo, and vanilla-checkpointing baselines in the same training setup for direct comparison. Multi-device long-context methods are acknowledged as complementary but are not the focus of our single-device experiments \cite{liu-2023-ringattention}.

\section{Background}
\subsection{Problem Setting and Memory Decomposition}
We consider decoder-only Transformers for language modeling trained on a single GPU. Training memory consists of: (a) parameters and optimizer states, often two to three times the raw parameter footprint due to moments; (b) the activation stack, i.e., forward activations cached for backpropagation across layers; and (c) temporary workspaces for kernels, notably attention and FFN. For 50-300M parameter models with moderate sequence lengths, these terms frequently exceed 20 GB, precluding end-to-end training on 8-16 GB devices.

\subsection{Reversible Residual Networks}
A reversible block splits its input along the feature dimension into two partitions \((x_1, x_2)\) and applies functions \(F\) and \(G\) such that \(y_1 = x_1 + F(x_2)\) and \(y_2 = x_2 + G(y_1)\). During backpropagation, the inputs are reconstructed by recomputation rather than by loading cached activations: \(x_2 = y_2 - G(y_1)\) and \(x_1 = y_1 - F(x_2)\). This removes the need to store per-layer activations and allows deep stacks under tight memory, at the cost of recomputation \cite{kitaev-2020-reformer}. MEFT shows adapters can be inserted into existing PLMs to enable reversibility without additional pretraining \cite{liao-2023-make}.

\subsection{Parameter-Efficient Updates and Rank Accumulation}
Low-rank adapters parameterize updates as \(\Delta = A B^{\top}\) with small rank \(r\), substantially reducing the number of trainable parameters and optimizer state compared to full fine-tuning \cite{he-2021-towards}. ReLoRA periodically merges \(\Delta\) into a base weight, approximating high-rank training while keeping the active trainable state small \cite{lialin-2023-relora}. SURM proposes structured matrices that achieve unrestricted (effective) rank with compact parameterizations, offering a stronger compactness-expressiveness trade-off than pure low-rank factors \cite{sehanobish-2024-structured}.

\subsection{In-Place Normalization and Activation}
Standard GELU and LayerNorm create extra buffers during forward and backward passes. In-place-friendly alternatives reduce or share intermediates, lowering peak memory \cite{andoorveedu-2022-tempo}. Approximate backpropagation and memory sharing across layers can further reduce activation memory \cite{yang-2024-reducing}.

\subsection{Blockwise Kernels for Long Contexts}
Processing attention and FFN in blocks bounds workspace memory and promotes near-linear growth with sequence length. Such blockwise computation is compatible with reversible architectures and is effective on a single device \cite{liu-2023-blockwise}.

\subsection{Assumptions and Scope}
We target single-device training under tight memory. The shared bases are stored with per-channel int8 scales, adapters are trained in mixed precision, and optional K-FAC for adapters stores factors on CPU \cite{eschenhagen-2023-kronecker}. Multi-device long-context methods are complementary and out of scope for our single-device focus \cite{liu-2023-ringattention}.

\section{Method}
\subsection{Model Parameterization}
For every linear projection in self-attention (query, key, value, and output) and in the feedforward network (the two dense layers), we represent the weight matrix as \(W = U_s + \Delta\). Here \(U_s\) is a frozen shared base reused across all layers of the same shape and stored in int8 with per-out-channel scaling to reduce quantization error. \(\Delta\) is a trainable low-rank matrix parameterized as \(A B^{\top}\) with small rank \(r\). We optionally initialize \(U_s\) with mild structure (for example, Toeplitz- or circulant-inspired smoothing) to emulate SURM-style expressiveness while keeping storage and access simple \cite{sehanobish-2024-structured}. Only \(A\) and \(B\) participate in the optimizer, bounding optimizer memory.

\subsection{ReLoRA-Style Merging}
To accumulate high effective rank without growing the trainable state, we periodically merge the current \(\Delta\) into \(U_s\). Every \(R\) steps, we compute \(\Delta = A B^{\top}\), update \(U_s \leftarrow U_s + \Delta\), re-quantize \(U_s\) with per-channel scaling, and reinitialize \(A\) and \(B\). This ReLoRA-style restart maintains learning dynamics while keeping the number of active trainable parameters small \cite{lialin-2023-relora}. Stable merges are encouraged by small adapter initialization scales and by per-channel rescaling of \(U_s\) upon each merge.

\subsection{Reversible Residual Skeleton}
Each transformer layer is implemented as a reversible block. The input is split into \((x_1, x_2)\). The attention sublayer acts as \(F\) and the feedforward network acts as \(G\). The forward pass computes \(y_1 = x_1 + F(x_2)\) and \(y_2 = x_2 + G(y_1)\). In backpropagation, \(x_1\) and \(x_2\) are reconstructed from \(y_1\) and \(y_2\) by recomputing \(F\) and \(G\), eliminating the need to store internal activations. Our adapter-augmented linear layers integrate with this skeleton without introducing additional stored activations.

\subsection{In-Place Operators}
We adopt in-place-friendly normalization and activation layers to reduce transient buffers. Tempo-style LayerNorm and a ReGELU2-like activation reduce or share intermediates while preserving forward behavior. These are compatible with the reversible formulation and our adapterized linear maps.

\subsection{Blockwise Attention and Chunked FFN}
To bound workspace memory, we employ blockwise attention kernels when available and compute FFN outputs in sequence chunks. This ensures that temporary activations scale with the chunk size, promoting near-linear memory growth with sequence length \cite{liu-2023-blockwise}. When available, fused or flash-style attention kernels further reduce memory and latency.

\subsection{Optimizer and Precision}
We train adapter parameters \(A\) and \(B\) with 8-bit AdamW by default, which further constrains optimizer state in GPU memory. Optionally, we apply K-FAC-reduce to adapters only, with curvature factors stored on CPU, leveraging weight-sharing-aware formulations \cite{eschenhagen-2023-kronecker}. Mixed precision (FP16 or BF16 with AMP) is used for compute. The shared base \(U_s\) remains in int8; adapters use FP16/BF16. Even-odd layer weight tying can be explored with a lightweight controller without increasing activation storage \cite{hay-2024-dynamic}.

\subsection{Memory Accounting and Expected Behavior}
Activation memory is reduced via reversibility and in-place operators; parameter and optimizer footprints are reduced by a single int8 shared base per shape with small low-rank adapters; and kernel workspaces are bounded by blockwise computation. Together, these measures are intended to fit 100-300M parameter models within 8-16 GB during training while maintaining competitive throughput. During inference, weight-only int8 paths allow the base to remain quantized with adapters in FP16, enabling memory- and latency-friendly deployment.

\subsection{Implementation Notes}
Per-out-channel scaling for the int8 base reduces quantization error and stabilizes periodic merges. During training, dequantization can be performed on-the-fly; for inference, weight-only int8 kernels avoid repeated dequantization. In ablations where reversibility is disabled, sequential checkpointing is enabled to ensure fair activation-memory comparisons.

\subsection{Algorithms}
\begin{algorithm}[t]
\caption{Periodic ReLoRA merge with shared int8 base}
\begin{algorithmic}[1]
\State Given base \(U_s\) (int8 with per-channel scales \(\gamma\)), adapters \(A, B\) (FP16/BF16), merge interval \(R\)
\For{each training step \(t = 1, 2, \dots\)}
  \State Dequantize base: \(\hat{U}_s \leftarrow \mathrm{dequant}(U_s, \gamma)\)
  \State Compute outputs with \(W_t = \hat{U}_s + A B^{\top}\)
  \State Backpropagate through adapters only; update \(A, B\) with optimizer
  \If{\(t \bmod R = 0\)}
    \State \(\Delta \leftarrow A B^{\top}\)
    \State \(\hat{U}_s \leftarrow \hat{U}_s + \Delta\)
    \State Quantize: \((U_s, \gamma) \leftarrow \mathrm{quant\_per\_channel}(\hat{U}_s)\)
    \State Re-init adapters: \(A \leftarrow \mathrm{init\_small}()\), \(B \leftarrow \mathrm{init\_small}()\)
  \EndIf
\EndFor
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{Reversible transformer block with recomputation}
\begin{algorithmic}[1]
\State Split input: \((x_1, x_2) \leftarrow \mathrm{split}(x)\)
\State Forward: \(y_1 \leftarrow x_1 + F(x_2)\); \(y_2 \leftarrow x_2 + G(y_1)\)
\State Concatenate output: \(y \leftarrow \mathrm{concat}(y_1, y_2)\)
\State During backward, given \(\nabla y_1, \nabla y_2\):
\State Reconstruct \(x_2 = y_2 - G(y_1)\) by recomputing \(G\)
\State Reconstruct \(x_1 = y_1 - F(x_2)\) by recomputing \(F\)
\State Backprop through \(F\) and \(G\) using recomputed inputs; accumulate \(\nabla x_1, \nabla x_2\)
\end{algorithmic}
\end{algorithm}

\section{Experimental Setup}
\subsection{Environment and Reproducibility}
All experiments are designed for a single NVIDIA RTX-3080-Ti (12 GB) with optional tests on an RTX-2060 (6 GB) for capacity stress. Software uses PyTorch with automatic mixed precision; bitsandbytes provides 8-bit optimizers and weight-only int8 storage; flash-style attention kernels are used when available. We fix random seeds across Python, NumPy, and CUDA; we fix tokenizer versions and data order. We log step-wise metrics, configurations, hardware metadata, and optionally energy via periodic nvidia-smi polling.

\subsection{Datasets and Tokenization}
Pretraining uses WikiText-103 with the GPT-2 BPE tokenizer. Fine-tuning targets Penn Treebank and GLUE tasks using official splits and metrics. All variants share tokenization, data order, and evaluation scripts.

\subsection{Models and Baselines}
We instantiate two sizes: GPT-Small at approximately 125M parameters (hidden size 768, 12 layers) and GPT-Medium at approximately 355M (hidden size 1024, 24 layers). Baselines include: (a) vanilla transformer with gradient checkpointing; (b) Reformer-like reversible-only backbone; (c) LoRA-style adapters on all projection layers; (d) MEFT; and (e) Tempo (in-place operators only). RASST matches hidden sizes and layer counts, uses adapter rank \(r = 32\), an int8 shared base reused across layers, reversible blocks, in-place operators, and blockwise kernels.

\subsection{Training Protocol and Fairness}
We equalize training signal by matching tokens-per-update across all variants using gradient accumulation. The learning rate schedule uses warmup followed by cosine decay. For RASST, we sweep the ReLoRA merge interval \(R \in \{500, 1000, 2000\}\) to balance stability and accumulation \cite{lialin-2023-relora}. Mixed precision uses AMP; TF32 matmuls may be enabled on supported hardware. Optional K-FAC-reduce is applied to adapters only with curvature factors stored on CPU \cite{eschenhagen-2023-kronecker}. We measure peak CUDA memory (allocated and reserved) after warmup, tokens per second as the median over the last third of training steps, validation perplexity on WikiText-103, and GLUE scores for fine-tuning. Energy estimates are optional.

\subsection{Ablations}
To attribute contributions, we remove one component at a time from full RASST: (1) no reversible (enable checkpointing); (2) no in-place operators (standard GELU and LayerNorm); (3) no structured shared base (replace with per-layer dense FP16 bases); (4) rank-0 adapters (shared base only). We report peak memory, throughput, validation perplexity, and an approximate split of parameter versus activation memory by subtracting parameter-state bytes from peak allocation.

\subsection{Long-Context Scaling and Low-Precision Robustness}
We examine sequence lengths 1024, 2048, and 4096 to fit memory scaling curves and throughput trends, comparing RASST to vanilla and reversible-only baselines \cite{liu-2023-blockwise}. For robustness and deployment, we fine-tune adapters on GLUE with weight-only int8 shared bases and FP16 adapters, targeting parity with FP16 inference within a small margin \cite{sehanobish-2024-structured}.

\subsection{Sanity Run Executed}
As a functionality check, we executed a tiny synthetic experiment: a small transformer with 2 layers and hidden size 128 for 10 steps on a synthetic\_uniform language modeling task, comparing RASST to vanilla under AMP. We recorded loss, peak allocated and reserved memory, and tokens per second. This run validates the code path and instrumentation but is not designed to assess real-data accuracy or throughput at realistic scales.

\section{Results}
\subsection{Sanity Experiment on a Tiny Synthetic Model}
We trained a 2-layer transformer with hidden size 128 for 10 steps on a synthetic\_uniform language modeling task, comparing RASST to a vanilla baseline under AMP. Both used identical settings aside from the architectural differences.

\subsection{Peak Memory}
RASST reduced peak memory versus vanilla in this tiny regime:
\begin{itemize}
  \item Peak allocated memory: RASST 231 MB; vanilla 286 MB (approximately 19\% reduction).
  \item Peak reserved memory: RASST 328 MB; vanilla 378 MB (approximately 13\% reduction).
\end{itemize}

\subsection{Throughput}
Tokens per second (tps) in this micro-scale setting were:
\begin{itemize}
  \item RASST last-step approximately 13.15k tps.
  \item Vanilla last-step approximately 23.50k tps.
\end{itemize}
This shows a slowdown of about 44\% for RASST relative to vanilla. Likely causes at tiny scale include per-step dequantization overheads for the int8 shared bases and recomputation costs dominating in the absence of fused kernels and larger kernel-saturating dimensions.

\subsection{Loss and Perplexity}
Training losses across 10 steps were similar between variants. Perplexity on synthetic\_uniform data is not meaningful for accuracy comparisons due to random labels and very short training.

\subsection{Interpretation and Relation to Prior Work}
The observed peak-memory savings are consistent with reversible training and in-place memory reductions. The throughput penalty at tiny scale is expected to diminish at realistic sizes and sequence lengths where kernel-level efficiencies dominate and blockwise kernels can be employed \cite{liu-2023-blockwise}. Weight-only int8 paths for the shared base further reduce overhead in inference settings \cite{sehanobish-2024-structured}.

\subsection{Fairness and Hyperparameters}
Both variants used the same architecture size, synthetic data source, mixed precision, and identical step counts. Because the run is short, we do not report confidence intervals.

\subsection{Limitations of Current Evidence}
The tiny synthetic setting cannot assess real-data accuracy or end-to-end throughput at scale. It likely understates memory savings that grow with depth and sequence length and overstates runtime overheads that are amortized on larger, kernel-saturating workloads.

\subsection{Planned Evaluations}
We will conduct end-to-end WikiText-103 pretraining on 125M and 355M models with matched token budgets, comparing RASST to vanilla with checkpointing, Reformer-like reversible, MEFT, LoRA-style, and Tempo baselines. We will report peak memory, tokens per second, validation perplexity, GLUE fine-tuning scores, and optional energy. Ablations will attribute savings to reversibility, in-place operators, the shared structured base, and adapter rank; long-context experiments will fit memory-versus-length curves; and GLUE finetuning will test weight-only int8 robustness \cite{liu-2023-blockwise}.

\section{Conclusion}
We presented RASST, a unified architecture that jointly collapses activation and parameter-state memory for training transformer language models on commodity GPUs. RASST combines a reversible residual skeleton, a shared per-channel-scaled int8 structured base reused across layers, low-rank adapters with periodic ReLoRA merges, in-place normalization and activation layers, and blockwise attention and chunked FFN, with optional K-FAC-reduce applied to adapters. A tiny synthetic sanity run already demonstrates a reduction in peak allocated and reserved memory relative to a vanilla baseline, validating the implementation and instrumentation. The observed micro-scale throughput penalty is expected to diminish at realistic scales with fused or blockwise kernels and weight-only int8 paths.

Our planned evaluation, conducted under matched token budgets and multiple seeds, will quantify memory savings, attribute contributions via ablations, assess near-linear memory growth with sequence length, and evaluate accuracy retention on WikiText-103 and GLUE. Future directions include learned SURM structures and FFT-friendly multiplies to improve inference speed, reinforcement-guided dynamic layer tying to expand parameter sharing, and integration with KV-cache compression for extended-context inference, complementing multi-device long-context strategies. More broadly, RASST suggests that combining reversible computation, structured weight sharing, and low-rank merging is a practical path to democratize end-to-end training of non-trivial language models within 8-16 GB memory budgets.
