\title{Unified Compressed Training: Budget-Aware Layer Policies for On-Device Fine-Tuning}

\author{AIRAS}

\maketitle

\begin{abstract}
On-device fine-tuning promises privacy and personalization, yet even sub-billion parameter language models exceed the training memory envelopes of 4-8 GB accelerators because activations, gradients, and optimizer states dominate. Prior work compresses one source at a time—reversible execution, activation projection, few-bit backward, or optimizer quantization—but naive combinations collide and no planner coordinates layer-wise choices under a strict budget. We introduce Unified Compressed Training (UCT), an end-to-end, budget-aware recipe that jointly compresses activations, derivatives, and optimizer state. UCT provides a Hybrid Compression Library exposing per-block variants (reversible, VeLoRA-style rank-1 sub-token projection, or normal storage), a greedy Budget-Aware Planner that selects per-layer variants and bit-widths to meet a user-specified VRAM budget, and a runtime controller that live-switches layers to prevent out-of-memory. A drop-in API targets HuggingFace models. We verify correctness and the expected memory-compute trade-off in a toy quick test on a Tesla T4: UCT reduces peak memory versus LoRA at accuracy parity, with slower throughput due to recomputation. We also detail a complete evaluation plan on MobileLLM-scale and 0.5B proxies across GLUE, WikiText-2, and Alpaca, including ablations of the planner, derivative bit-widths, optimizer quantization, and OOM-prevention stress tests.
\end{abstract}

\section{Introduction}
Personalized, private, and low-latency adaptation of language models requires training on resource-constrained devices. While parameter-efficient fine-tuning reduces the number of updated weights, activation storage and optimizer states remain the dominant training memory costs on 4-8 GB GPUs/NPUs for 100M-700M parameter models. Existing techniques ameliorate individual memory sources: reversible residual layers minimize stored activations by recomputation \cite{kitaev-2020-reformer}; adapterized reversible fine-tuning retains pretrained initialization \cite{liao-2023-make}; VeLoRA compresses activations via rank-1 sub-token projection \cite{miles-2024-velora}; Few-bit Backward quantizes pointwise derivatives to 2-4 bits \cite{novikov-2022-few}; and Any-Precision formats compact optimizer state \cite{park-2024-any}. System schedulers optimize checkpoint placement and memory layouts \cite{chen-2016-training,shah-2020-memory,zhang-2023-coop}. However, naive combinations collide: reversible execution can conflict with checkpointing assumptions and numerical stability; activation projection may perturb normalization statistics if applied uniformly; and no mechanism assigns heterogeneous per-layer policies under a global VRAM budget.

We address this gap with Unified Compressed Training (UCT), a budget-aware training toolkit that co-optimizes three memory sources—activation storage, gradient/derivative representation, and optimizer states—while coordinating heterogeneous policies across layers. UCT targets sub-billion parameter Transformers destined for on-device use, complementing compact model families like MobileLLM \cite{liu-2024-mobilellm} and orthogonal PEFT and representation editing methods \cite{chen-2023-parameter,wu-2024-reft,sung-2022-lst,jiang-2023-res,zhang-2024-spectral,ai-2023-ntk}. UCT’s Hybrid Compression Library (HCL) offers, per Transformer block, three interchangeable variants: reversible computation, VeLoRA-style rank-1 activation projection, or standard storage. All variants use few-bit derivatives for pointwise operations and any-precision optimizer states. UCT’s Budget-Aware Planner (BAP) estimates per-layer memory/compute for each variant with analytic formulas and solves a greedy knapsack to meet a user-specified budget, preferring projection in lower layers and reversibility in upper layers. A runtime controller observes actual peaks and live-switches a worst-case layer to a cheaper variant to avert OOM. The user API is a single wrapper call.

\subsection{Why joint compression is challenging}
Jointly applying reversible execution, activation projection, and derivative quantization at layer granularity raises numerical and scheduling challenges; optimizer quantization must remain robust across heterogeneous policies; and planning must reason about non-uniform costs while preserving accuracy. Literature addresses pieces of this space—reversible Transformers \cite{kitaev-2020-reformer}, activation compression \cite{miles-2024-velora}, few-bit derivatives \cite{novikov-2022-few}, any-precision states \cite{park-2024-any}, and memory schedulers \cite{chen-2016-training,shah-2020-memory,zhang-2023-coop}—but not a unified, budget-aware integration.

\subsection{Contributions}
\begin{itemize}
\item \textbf{Hybrid Compression Library}: A layer-wise library combining reversible computation \cite{kitaev-2020-reformer}, VeLoRA-style projection \cite{miles-2024-velora}, and normal storage, with Few-bit Backward \cite{novikov-2022-few} and Any-Precision optimizer states \cite{park-2024-any}.
\item \textbf{Budget-Aware Planner}: Analytic per-layer estimates and a greedy knapsack that assigns heterogeneous policies under a VRAM budget, with simple topology-aware priorities.
\item \textbf{Runtime engine and controller}: Custom autograd and a live controller that prevents OOM by switching layers when measured usage exceeds budget, drawing on memory scheduling and fragmentation insights \cite{shah-2020-memory,zhang-2023-coop}.
\item \textbf{Evaluation program}: An experimental plan on GLUE, WikiText-2, and Alpaca for MobileLLM-scale and ~0.5B proxies on 4-8 GB devices, including ablations of planner, derivative bit-width, and optimizer quantization; plus an executed toy quick test on a Tesla T4 confirming memory advantage at accuracy parity with expected throughput overhead.
\end{itemize}

\subsection{Relation to broader trends}
UCT complements architectural and sequence-length efficiency (for example, blockwise parallelism \cite{liu-2023-blockwise}, compute-lean backbones \cite{ding-2024-memoryformer}) by focusing on training-time memory budgets without altering pretrained architectures. It preserves standard backpropagation, contrasting with forward-only optimization such as MeZO \cite{malladi-2023-fine}, and aligns with approximate or memory-sharing backpropagation perspectives \cite{yang-2024-reducing}. We conclude with limitations and future work: integrating mixed-precision weight quantization into planning, learning policies via reinforcement learning, and applying UCT to multimodal and speech Transformers, all while maintaining compatibility with evolving PEFT design spaces \cite{chen-2023-parameter}.

\section{Related Work}
\subsection{Memory-efficient execution}
Reversible residual layers can eliminate per-layer activation storage by reconstructing activations during backpropagation \cite{kitaev-2020-reformer}. MEFT adapts pretrained models into reversible forms via adapters while preserving initialization, cutting activation memory relative to full fine-tuning \cite{liao-2023-make}. Classic checkpointing achieves sublinear memory by recomputation \cite{chen-2016-training}, while MONeT automates checkpoint schedules and operator implementations to jointly reduce memory and compute overhead \cite{shah-2020-memory}. Coop co-optimizes tensor allocation and rematerialization to mitigate fragmentation and reduce overhead \cite{zhang-2023-coop}. UCT differs by coordinating reversible execution with activation projection, derivative quantization, and optimizer quantization via a planner that emits heterogeneous per-layer policies under a fixed budget; prior approaches optimize within a single axis or at operator level without cross-axis planning.

\subsection{Activation and gradient compression}
VeLoRA demonstrates that forward activations can be aggressively compressed by projecting sub-tokens onto a fixed one-dimensional subspace and coarsely reconstructing them during backward, yielding substantial memory savings with minimal quality loss \cite{miles-2024-velora}. Few-bit Backward quantizes the derivatives of pointwise nonlinearities with optimal piecewise-constant approximations, retaining convergence with as few as 2-4 bits \cite{novikov-2022-few}. Approximate and memory-sharing backpropagation decouples forward/backward for selected functions and shares memory across layers \cite{yang-2024-reducing}. UCT integrates these ideas but applies them selectively per layer through a planner, avoiding the pitfalls of uniform compression which can degrade normalization or residual dynamics.

\subsection{Optimizer quantization}
Any-Precision LLM compresses tensors to variable bit-widths with a specialized engine \cite{park-2024-any}. UCT adopts the any-precision principle for optimizer states, starting at low bit-width and up-scaling on divergence, and coordinates this choice with activation and derivative compression under a global budget. Prior work does not couple optimizer precision with layer-wise activation policies.

\subsection{Parameter-efficient and representation tuning}
Design-space analyses reveal structural patterns across PEFT methods \cite{chen-2023-parameter}. Representation fine-tuning modifies hidden states directly \cite{wu-2024-reft}; Ladder Side-Tuning attaches a side network to avoid backprop through the backbone \cite{sung-2022-lst}; Res-Tuning unbinds tuners from the backbone \cite{jiang-2023-res}; Spectral Adapter leverages singular vectors \cite{zhang-2024-spectral}; and NTK-aware MLP fusion preserves training dynamics while compressing MLPs \cite{ai-2023-ntk}. These methods target parameter or compute efficiency rather than end-to-end training memory orchestration. UCT is orthogonal and can wrap models using these tuners.

\subsection{Architectural and long-context efficiency}
Blockwise Parallel Transformers reduce memory via blockwise attention and FFN fusion \cite{liu-2023-blockwise}; MemoryFormer reduces FLOPs by replacing fully connected layers with memory lookups \cite{ding-2024-memoryformer}. These require architecture changes. UCT assumes fixed pretrained architectures and focuses on training-time memory. MobileLLM demonstrates that sub-billion parameter models can perform competitively for on-device applications \cite{liu-2024-mobilellm}, making training-time memory a key bottleneck. MeZO pursues forward-only optimization with inference-level memory \cite{malladi-2023-fine}; UCT retains backpropagation while compressing its memory sources.

\subsection{Contrast and applicability}
While reversible PEFT \cite{liao-2023-make} reduces activation storage, it does not plan across layers under a global budget. VeLoRA \cite{miles-2024-velora} compresses activations but does not address optimizer state or derivative storage. MONeT \cite{shah-2020-memory} and Coop \cite{zhang-2023-coop} optimize memory layouts and checkpointing but do not incorporate activation projection or optimizer quantization. UCT contributes a unified, budget-aware planner that chooses heterogeneous layer policies and a runtime controller that enforces safety, capabilities absent from prior single-axis or uniform methods.

\section{Background}
\subsection{Problem setting}
We consider fine-tuning a pretrained Transformer with L blocks on a device with a strict VRAM budget B. Training memory includes: (1) stored activations needed for backpropagation, (2) temporary buffers during backward, (3) derivatives for pointwise operations, (4) gradients and optimizer states (for example, momentum and variance), and (5) framework overhead and fragmentation. Each layer l exposes a variant v in the set {reversible, projection, store}. Variants trade off activation memory and compute: reversible recomputes activations during backward to avoid storing them \cite{kitaev-2020-reformer}; projection saves a rank-1 sub-token representation per token and reconstructs coarsely in backward \cite{miles-2024-velora}; store keeps full activations. Few-Bit Backward reduces derivative memory by k-bit piecewise-constant approximations \cite{novikov-2022-few}. Optimizer states are kept in an any-precision format and can be up-scaled if instability occurs \cite{park-2024-any}.

\subsection{Formalization}
For a sequence length s and micro-batch size b, define, for each layer l and variant v, the activation memory \(M_{\text{act}}(l, v; s, b)\) and compute costs for forward and backward, \(C_{\text{fwd}}(l, v)\) and \(C_{\text{bwd}}(l, v)\). Derivative memory \(M_{\text{deriv}}(k)\) depends on the number of pointwise operations and the chosen k-bit tables. Optimizer memory \(M_{\text{opt}}(q)\) scales with the trainable parameter count and precision q. The estimated peak training memory is the maximum across execution phases of the sum over layers of \(M_{\text{act}}\) plus \(M_{\text{deriv}}(k)\) and \(M_{\text{opt}}(q)\), plus overhead. The budgeted policy selection problem is to choose per-layer variants \(v_l\) and global derivative/optimizer bit-widths k and q so that the estimated peak does not exceed B while keeping accuracy and compute overhead acceptable.

\subsection{Heuristics and priorities}
Exact accuracy models for variant choices are unavailable. Two empirical priorities guide selection: (1) assign projection to lower layers to preserve semantic features while compressing storage; (2) assign reversible to higher layers where activations are larger and recomputation is relatively cheaper. We keep derivative quantization within 2-4 bits and begin optimizer state at low precision with the option to up-scale on divergence. These heuristics are consistent with reversible execution and activation compression literature \cite{kitaev-2020-reformer,miles-2024-velora}, Few-Bit Backward \cite{novikov-2022-few}, Any-Precision \cite{park-2024-any}, and memory scheduling insights \cite{chen-2016-training,shah-2020-memory,zhang-2023-coop}.

\subsection{Assumptions}
We assume pretrained weights and normalization statistics remain in their standard precision during forward; Few-Bit Backward only changes derivative computation for pointwise operators \cite{novikov-2022-few}; and any-precision optimizer states can be safely up-scaled without information loss over short windows \cite{park-2024-any}. We avoid global integer programming in favor of analytic estimates and greedy selection for robustness and speed. UCT complements compact architectures \cite{liu-2023-blockwise,ding-2024-memoryformer} and on-device model design \cite{liu-2024-mobilellm} while preserving conventional backpropagation rather than adopting forward-only schemes \cite{malladi-2023-fine}.

\section{Method}
UCT comprises three components designed to satisfy a user-specified VRAM budget while preserving training behavior.

\subsection{Layer-wise Hybrid Compression Library}
\textbf{Reversible (A)}: The block’s forward computation is made reversible; intermediate activations are not stored and are reconstructed during backward by replaying the forward mapping \cite{kitaev-2020-reformer}. This makes activation memory per layer negligible but increases backward compute due to rematerialization.

\textbf{Rank-1 sub-token projection (B)}: Before storing per-layer activations, split each token into sub-tokens and project onto a fixed one-dimensional subspace. Store only the resulting scalar sequence and minimal metadata; reconstruct an approximation during backward \cite{miles-2024-velora}. Stored activations scale with \(b\times s\) rather than \(b\times s\times d\).

\textbf{Normal store (C)}: Standard training that saves full activations.

Across all variants, pointwise nonlinearities use Few-Bit Backward with k-bit piecewise-constant derivative tables (default \(k=3\)) \cite{novikov-2022-few}. Optimizer states for trainable parameters follow an any-precision schedule (for example, 8-4-2 bits), with an online divergence monitor that triggers up-scaling if the loss increases persistently, following the spirit of Any-Precision LLM \cite{park-2024-any}. HCL wraps common PEFT or representation-tuning approaches \cite{chen-2023-parameter,wu-2024-reft,sung-2022-lst,jiang-2023-res,zhang-2024-spectral,ai-2023-ntk}.

\subsection{Budget-Aware Planner}
\textbf{Inputs}: budget B, sequence length s, micro-batch b, model topology (L layers, hidden sizes), derivative bit options \(K=\{2,3,4\}\), optimizer precisions Q.

\textbf{Static estimation}: Trace the graph once to obtain per-layer shapes and buffers. Compute analytic estimates for each variant v: Store scales as \(\mathcal{O}(b\times s\times d)\), Projection as \(\mathcal{O}(b\times s\times 1)\) plus metadata, Reversible near zero per layer. Add derivative memory \(M_{\text{deriv}}(k)\) and optimizer state \(M_{\text{opt}}(q)\). Include fixed safety margins informed by scheduling literature \cite{chen-2016-training,shah-2020-memory,zhang-2023-coop}.

\textbf{Initialization}: Start from a high-quality plan (for example, normal store everywhere) and iteratively replace layers with cheaper variants, or initialize from a mixed heuristic (projection for lower third, reversible for upper third) when the budget is tight.

\textbf{Greedy knapsack}: Rank candidate layer changes by memory saved per unit compute overhead. Apply changes until the estimated peak is within B. Prefer projection over reversible when both suffice, unless topology priorities recommend otherwise.

\textbf{Global bit-widths}: Choose k in K to fit the budget with minimal increase in error risk; select initial optimizer precision q and divergence thresholds for up-scaling.

\begin{algorithm}[H]
\caption{Budget-Aware Planner (BAP)}
\begin{algorithmic}
\State \textbf{Input:} budget B, seq length s, micro-batch b, layers \(\{1,\dots,L\}\), shapes \(\{d_l\}\), options \(K, Q\)
\State \textbf{Output:} per-layer policy \(\{v_l\}\), derivative bits k, optimizer precision q
\State Initialize \(v_l \leftarrow \text{store}\) for all l; set default \(k \leftarrow 3\), \(q \leftarrow q_{\text{low}}\)
\State Estimate per-layer activation costs \(M_{\text{act}}(l, v)\) and compute costs \(C(l, v)\) for \(v\in\{\text{store}, \text{proj}, \text{rev}\}\)
\State Compute non-activation costs \(M_{\text{deriv}}(k), M_{\text{opt}}(q)\)
\State \(\hat{M} \leftarrow \max\) over phases of total estimated memory with current plan
\If{\(\hat{M} \le B\)} \Return current plan \EndIf
\State Build candidate list \(\mathcal{C} \leftarrow \{(l, v\to v')\}\) with \(v'\in\{\text{proj},\text{rev}\}\) and current \(v\ne v'\)
\For{each candidate c in \(\mathcal{C}\)}
  \State Compute memory saving \(\Delta M(c)\) and compute overhead \(\Delta C(c)\)
  \State Score \(\rho(c) \leftarrow \Delta M(c) / (\Delta C(c)+\epsilon)\)
  \State Apply topology prior: boost \(\rho\) for lower layers choosing proj and upper layers choosing rev
\EndFor
\While{\(\hat{M} > B\)}
  \State Select \(c^* \leftarrow \arg\max_{c\in\mathcal{C}} \rho(c)\)
  \State Apply \(c^*\) to update the plan; remove conflicting candidates
  \State Recompute \(\hat{M}\); if no candidates remain, break
\EndWhile
\If{\(\hat{M} > B\)}
  \For{\(k'\in\) K in increasing order}
    \State Tentatively set k \(\leftarrow k'\), recompute \(M_{\text{deriv}}(k)\) and \(\hat{M}\)
    \If{\(\hat{M} \le B\)} \textbf{break} \EndIf
  \EndFor
\EndIf
\State Return final \(\{v_l\}\), k, q
\end{algorithmic}
\end{algorithm}

\subsection{Runtime engine with live controller}
\textbf{Variant switching}: Custom autograd functions expose reversible and projected paths so a layer can switch variants by flipping a flag. This enables the planner’s policy to be injected pre-training and adjusted online.

\textbf{Live OOM prevention}: A controller monitors actual peak memory. If the observed usage exceeds B, it selects the worst offending layer (for example, a projected layer with high stored activations) and switches it to a cheaper variant (usually projection to reversible), then resumes training. The controller is lightweight and targets a small throughput penalty. Its design is informed by fragmentation-aware work \cite{zhang-2023-coop} and checkpointing overhead analyses \cite{shah-2020-memory}.

\begin{algorithm}[H]
\caption{Live OOM-Prevention Controller}
\begin{algorithmic}
\State \textbf{Input:} budget B, current plan \(\{v_l\}\), monitoring window T
\While{training}
  \State Measure peak usage \(M_{\text{peak}}\) over last T steps
  \If{\(M_{\text{peak}} \le B\)} \textbf{continue}
  \EndIf
  \State Identify candidate layers \(\mathcal{L}\) with highest activation footprint under current \(\{v_l\}\)
  \For{\(l \in \mathcal{L}\)}
    \If{\(v_l = \text{proj}\)} \State propose \(v_l \leftarrow \text{rev}\); \textbf{break}
    \ElsIf{\(v_l = \text{store}\)} \State propose \(v_l \leftarrow \text{proj}\); \textbf{break}
    \EndIf
  \EndFor
  \State Apply change; synchronize autograd hooks; resume training
\EndWhile
\end{algorithmic}
\end{algorithm}

\subsection{Design interactions and stability}
\textbf{Normalization}: Projection operates on stored tensors rather than altering forward normalization statistics; the forward pass remains unchanged to protect stability.

\textbf{Accuracy-compute trade-off}: Reversibility reduces memory most but adds recomputation; projection offers a middle ground. BAP encodes these trade-offs in its ranking. When multiple configurations fit B, BAP prefers the one with lower estimated compute.

\subsection{Extensions and scope}
UCT can incorporate attention/FFN fusion or blockwise processing \cite{liu-2023-blockwise} via refined cost models, and it complements compute-lean backbones \cite{ding-2024-memoryformer}. While forward-only MeZO \cite{malladi-2023-fine} achieves inference-level memory, UCT preserves full backpropagation and integrates with standard PEFT regimes \cite{chen-2023-parameter}. An important future extension is to add mixed-precision weight quantization as a first-class decision variable in BAP.

\section{Experimental Setup}
\subsection{Evaluation program and goals}
We target sub-billion parameter models across three backbones: (i) a MobileLLM-scale causal LM (~350M parameters), (ii) a ~0.5B causal LM proxy, and (iii) T5-small (110M) for encoder-decoder tasks. Tasks: GLUE classification, WikiText-2 language modeling, and Alpaca-52k instruction fine-tuning. Memory budgets: 3-6 GB to reflect 4-8 GB devices. Baselines: Full fine-tuning when it fits; LoRA with r=8; 8-bit optimizer; gradient checkpointing; and, when available, VeLoRA and MONeT as strong memory-efficiency references \cite{miles-2024-velora,shah-2020-memory}. Additional comparisons to reversible PEFT are relevant \cite{liao-2023-make}. UCT defaults: rank=1 projection; \(k=3\)-bit derivatives; any-precision optimizer states with conservative up-scaling; greedy planner; runtime controller enabled.

\subsection{Hardware and precision}
Primary device is a single RTX 2060 (6 GB), with optional replication on Jetson Orin (8 GB). Mixed precision uses fp16 on RTX and bf16 if supported on Orin. All methods share the same precision settings for fairness.

\subsection{Hyperparameters and training protocol}
Optimizer is AdamW for Full FT and LoRA; any-precision variant is used inside UCT \cite{park-2024-any}. Typical learning rates are 2e-5 for GLUE and 1e-4 for language modeling, with linear decay and 5\% warmup. Gradient clipping is 1.0. Epoch counts: 3 for GLUE and Alpaca subsets; for WikiText-2 we run either a fixed number of steps or 3 epochs over tokenized shards.

\subsection{Batching under budgets}
For each method and budget B, we probe to find the largest micro-batch that fits without OOM at the target sequence length. When feasible, we fix the same micro-batch across methods for comparable throughput and convergence dynamics. Sequence lengths: 512 for GLUE and 1024 for WikiText-2 and Alpaca.

\subsection{Metrics and measurement}
We record peak resident GPU memory (max of reserved/allocated), throughput (tokens per second), wall-clock epoch time, and task metrics: GLUE accuracy/F1, WikiText-2 perplexity, and Alpaca held-out loss or simple instruction evaluation. Additional compute overhead is reported as the percentage increase in time per token relative to LoRA. We log planner estimates and compute the mean absolute percentage error (MAPE) between estimated and measured peak memory to assess BAP accuracy.

\subsection{Ablations and diagnostics}
\begin{itemize}
\item \textbf{Planner ablation}: replace BAP with uniform policies (all reversible, all projection, or all store if feasible) to test the value of heterogeneous policies.
\item \textbf{Optimizer quantization}: disable any-precision to quantify its memory impact and stability.
\item \textbf{Derivative bit-width}: sweep \(k\in\{2,3,4\}\) to test sensitivity.
\item \textbf{Static vs adaptive}: disable the controller to assess OOM incidence and throughput penalty under dynamic workloads.
\end{itemize}
Per-layer policy quality is summarized by the fraction of layers in the lower third assigned projection and in the upper third assigned reversible.

\subsection{Runtime stress test}
We evaluate OOM prevention with a curriculum that increases the maximum sequence length across phases (for example, 512-1024-1536-2048) at a budget near the device limit. We compare UCT with controller on versus off and a LoRA baseline under the same curriculum, recording OOM counts and throughput penalty.

\subsection{Executed quick test}
As a sanity check of correctness and the anticipated memory-compute trade-off, we executed a toy experiment on a Tesla T4 GPU using a synthetic sequence classification dataset and a 4-layer ToyTransformer (model dimension 64). Batch size was 16, sequence length 32, and each method trained for two epochs. UCT used a budget of approximately 0.10 GB, rank=1, \(k=3\)-bit derivatives, the greedy planner, the controller enabled, and any-precision optimizer states. The LoRA baseline used r=4 and alpha=8 with AdamW on trainable parameters. Metrics logged were peak GPU memory, tokens per second, validation loss, and validation accuracy. This quick test is not a substitute for the full evaluation on standard datasets and larger models but validates mechanisms and instrumentation. The complete experimental harness follows the standard memory-efficient execution literature \cite{chen-2016-training,zhang-2023-coop} and compares to activation compression and PEFT baselines \cite{miles-2024-velora,liao-2023-make,chen-2023-parameter}.

\section{Results}
\subsection{Toy quick test outcomes}
On the synthetic task with a 4-layer ToyTransformer (d\_model=64), batch size 16, sequence length 32, and two epochs per method on a Tesla T4, we obtained:
\begin{itemize}
\item UCT: validation accuracy 1.000 in both epochs; validation loss 0.0294 (epoch 1) and 0.2509 (epoch 2); peak resident GPU memory 0.029 GB; throughput 9,519 and 13,124 tokens/s across epochs (mean approximately 11,322 tokens/s).
\item LoRA: validation accuracy 1.000 in both epochs; validation loss 0.0677 (epoch 1) and 0.0132 (epoch 2); peak resident GPU memory 0.033 GB; throughput 35,570 and 43,189 tokens/s across epochs (mean approximately 39,380 tokens/s).
\end{itemize}

\subsection{Analysis}
UCT reduced peak memory by about 0.004 GB relative to LoRA, or roughly 12\% in this small regime, confirming that jointly compressing activations, derivatives, and optimizer states can reduce training footprint beyond adapter-only fine-tuning. As expected from reversible recomputation and runtime machinery, UCT’s throughput was lower (about 3.4\times slower on average) while maintaining accuracy parity on the synthetic task. The runtime controller did not switch policies because usage remained below the specified budget; no OOM events occurred. These observations are consistent with the intended combination of reversible execution \cite{kitaev-2020-reformer}, activation projection \cite{miles-2024-velora}, Few-Bit Backward \cite{novikov-2022-few}, and any-precision optimizer states \cite{park-2024-any}.

\subsection{Fairness and controls}
Both methods used identical datasets, epochs, batch size, and sequence length. Because absolute memory was small (tens of megabytes), percentage differences are magnified; thus, these outcomes should be interpreted as a sanity check of mechanisms and instrumentation rather than indicative of the 4-8 GB regime. Planner ablations, derivative bit-width sweeps, optimizer quantization ablations, and long-context stress tests were not executed in this quick test.

\subsection{Limitations and next steps}
The toy setup does not exercise BAP at scale, nor does it probe long contexts or dynamic curricula. Throughput penalties may differ for larger models where activation memory dominates and reversibility yields larger savings. Executing the full evaluation plan on GLUE, WikiText-2, and Alpaca with ablations and stress tests is required to establish Pareto fronts and quantify the benefits of planner-driven heterogeneous policies relative to strong baselines including MONeT \cite{shah-2020-memory}, reversible PEFT \cite{liao-2023-make}, and VeLoRA \cite{miles-2024-velora}.

\section{Conclusion}
We presented Unified Compressed Training, a budget-aware training toolkit that unifies layer-wise reversible execution, rank-1 activation projection, Few-Bit Backward derivatives, and Any-Precision optimizer states. A greedy Budget-Aware Planner assigns heterogeneous policies per layer to fit a user-specified VRAM budget, and a runtime controller prevents out-of-memory by live-switching layers when peaks exceed the budget. A simple wrapper API targets mainstream Transformer implementations and is compatible with PEFT and representation-tuning methods.

A toy quick test confirmed UCT’s core behavior: lower peak memory than a LoRA baseline at the same accuracy on a synthetic task, with expected throughput overhead due to recomputation. The complete evaluation plan targets sub-billion models on 4-8 GB devices across GLUE, WikiText-2, and Alpaca with baselines, ablations, and OOM-prevention stress tests to quantify memory-accuracy-throughput trade-offs and the value of planner-driven heterogeneous policies. Academically, UCT demonstrates the feasibility of jointly compressing activations, derivatives, and optimizer states under a global budget, extending beyond single-axis or uniform approaches \cite{kitaev-2020-reformer,miles-2024-velora,novikov-2022-few,park-2024-any,chen-2016-training,shah-2020-memory,zhang-2023-coop}. Practically, UCT aims to enable on-device fine-tuning of sub-1B LMs on commodity 4-8 GB hardware, complementing compact model design and PEFT design spaces \cite{liu-2024-mobilellm,chen-2023-parameter,wu-2024-reft,sung-2022-lst,jiang-2023-res,zhang-2024-spectral,ai-2023-ntk}. Future work includes extending BAP to mixed-precision weight quantization, learning policies via reinforcement learning, integrating advances in memory scheduling \cite{zhang-2023-coop,shah-2020-memory}, and evaluating UCT on multimodal and speech Transformers, while also exploring forward-only optimization as an alternate operating mode \cite{malladi-2023-fine}.
